# 后台管理-项目管理设计文档

## 1. 目的与边界

本文定义 Web 管理后台的项目治理页面和调用服务端项目 API 的规则。

后台负责项目创建、编辑、激活、归档、项目成员、项目资产关联和项目审计的页面；服务端负责项目数据、权限、并发控制和审计的最终结果。

本轮不提供代码源设置、代码克隆、工作区操作、资产上传、任务、Run、Git、Agent Pool、MCP、预算或交付审核页面。

## 2. 导航与路由

后台保留两级导航，并增加独立一级菜单“项目管理”：

```text
项目管理
  └─ 项目列表
权限管理
  ├─ 用户与成员
  ├─ 角色与权限
  ├─ 项目授权
  └─ 授权审计
```

项目列表路由为 `/projects`，项目详情路由为 `/projects/{project_id}`。详情页签使用 `tab=overview|members|assets|audit` 或等价稳定子路由表达；每次页面读取仍由服务端鉴权。

“权限管理 / 项目授权”继续提供跨组织、跨项目的成员授权汇总；项目详情的成员页提供项目上下文内的同一关系管理。两处使用同一服务端 API，不建立第二套成员数据。

## 3. 会话与访问守卫

后台使用 Auth.js HttpOnly Session。浏览器只保存会话 Cookie，服务端路由或 API 代理代持用户服务访问令牌；Token 不进入客户端存储、URL、日志或页面数据。

只有 `admin` 和 `manager` 能看到“项目管理”和“权限管理”。`admin` 的项目数据和操作覆盖全平台；`manager` 仅覆盖账号有效加入的组织；`member` 隐藏管理菜单，直接访问路由或接口也不得获得项目治理数据。

页面进入、组织筛选、项目详情读取和每次写入都由服务端重新确认 Session、账号状态、角色、组织范围和项目状态。不可见资源优先显示 404；可见但不允许的操作显示 403，前端不通过隐藏按钮替代服务端鉴权。

后台不消费服务端 `allowed_actions` 字段，也不提交前端计算的权限结果。控件显示只依据服务端返回的全局角色、项目状态、项目组织和当前组织成员关系套用固定角色矩阵；每个写请求仍由服务端逐请求鉴权。

## 4. 项目列表页

列表默认显示 `active` 和 `draft`，`archived` 通过明确状态筛选读取。页面提供组织、状态和名称关键字筛选；当前页面不提供更新时间排序或游标分页控件，直接显示服务端返回的完整列表，内存服务默认按 `updated_at desc, project_id asc` 排序。

生产服务接口仍应支持稳定排序和游标分页；后台在接入分页服务前不得自行拼接或截断项目列表，也不得把当前完整列表响应当成生产分页协议。

服务端列表响应应提供项目名称、所属组织、状态、更新时间、创建人、成员数量、资产关联数量和修订号；当前列表行展示名称、组织、修订号、更新时间和状态，成员/资产数量在项目详情概览展示。列表不显示代码源、仓库地址、本机路径、资产全文或隐藏项目数量。

列表提供“创建项目”操作；不提供删除、批量激活、批量归档或批量资产关联。每个写操作单独提交、单独显示结果并单独产生审计事件。

## 5. 创建和编辑

创建表单只包含所属组织、项目名称和可选描述。

`admin` 可以选择任意可管理组织；`manager` 只能选择自己有效加入的组织。客户端必须显式提交 `organization_id`，不能从当前筛选条件推断。

项目名称去除首尾空白后为 1-80 个字符，不得包含控制字符或路径分隔符；同一组织内非归档项目名称大小写不敏感唯一。描述最长 2,000 个字符。

创建成功后项目固定为 `draft`，页面显示服务端生成的 `project_id`、`revision` 和时间。成员、资产关联和激活分别在详情页配置。

普通编辑只允许修改名称和描述；`project_id`、`organization_id`、`created_by`、创建时间不可修改。编辑请求携带当前修订号和幂等键；当前客户端通过 `If-Match` 请求头传递修订号，成功后以服务端响应替换表单数据。

## 6. 项目详情页签

### 6.1 概览

概览显示名称、描述、所属组织、状态、创建人、创建时间、更新时间、修订号和可见的成员/资产数量。

草稿显示“激活”操作；active 显示“归档”操作；archived 只读。激活只要求组织有效和名称合法，页面可以提示尚未配置成员或资产，但不得阻止激活或自动改变状态。

激活和归档使用确认对话框和显式动作接口。归档后项目不可恢复、不可继续编辑、不可新增或移除成员、不可新增或解除资产关联。

### 6.2 成员

成员页显示项目所属组织内的 active `member` 账号、成员状态、加入时间和关系修订号。`admin` 可管理全平台项目成员；`manager` 只能管理自己组织的 member；项目成员不新增 owner/editor 等项目角色。

添加、更新和移除成员均是单条服务端操作，携带当前关系或项目的修订号和 `Idempotency-Key`；当前客户端通过 `If-Match` 请求头传递修订号，新关系使用项目修订号，已有关系使用关系修订号。服务端失败时保留表单输入，不显示本地成功；当前页面不会自动重读，用户通过刷新操作重新读取最新资源。

### 6.3 资产关联

资产关联页按 Skill、知识库和记忆分组，并区分 `reference` 与 `context`。生产页面的候选资产来自对应资产模块的服务端授权查询；当前联调页面让管理员直接输入不透明 `asset_id`，项目服务不接收资产全文，也不负责上传。

新增、修改关系类型和解除关联分别调用单条接口。每条关联有独立修订号；同一项目内同一资产只能存在一种关系。`context` 只标记未来云端任务候选，不自动注入 DSH 原生会话。

项目管理不通过浏览器过滤全部资产来判断权限。服务端必须同时检查操作者项目治理权限、资产模块管理权限、资产可见范围和项目组织兼容性。

### 6.4 审计

审计页默认限定当前项目。当前项目详情页直接读取项目范围记录并显示时间、操作者、动作、结果和请求编号；全局“授权审计”页只提供动作筛选。生产页面仍应使用服务端分页查询并支持时间、操作者、动作和结果筛选。它显示创建、编辑、激活、归档、成员变更、资产关联变更和权限拒绝等事件。

审计记录显示请求编号、操作者摘要、目标资源摘要、动作、结果、错误码、变更前后非敏感摘要和时间。审计是变更的记录，不是审批门；变更成功即生效并同步写入审计。

## 7. 并发、幂等和错误

所有创建、编辑、激活、归档、成员和资产关系写入都携带 `Idempotency-Key`，并携带 `expected_revision` 或 `If-Match`。

相同资源使用相同幂等键和相同请求内容时返回第一次结果；相同键提交不同内容返回 `409 IDEMPOTENCY_CONFLICT`。修订号过期返回 `409 REVISION_CONFLICT`，后台丢弃本地成功假设，不自动覆盖或合并；当前页面显示冲突消息并保留未提交表单，用户通过刷新操作读取最新数据后重新确认。

字段或状态非法返回 `422 VALIDATION_ERROR`；已知资源但当前操作者无操作权返回 `403 FORBIDDEN`；不可见资源返回 `404 RESOURCE_NOT_FOUND`。错误详情不得泄露其他组织、项目、成员、资产或审计记录的存在性。

服务不可用时显示重试状态，保留未提交表单内容；不以本地乐观状态标记创建、编辑、激活、归档或授权成功。

## 8. 后台验收

- `admin` 可创建草稿、编辑、激活、归档项目，并管理全平台项目成员和资产关联。
- `manager` 只能治理其加入组织内的项目，不能读取或写入其他组织项目。
- `member` 看不到项目管理和权限管理，直接路由访问不得获得项目治理数据。
- 项目详情四个页签使用同一服务端项目 ID 和修订号；成员页与“项目授权”数据一致。
- 资产关联候选经过资产模块授权，项目页不提供资产上传或资产全文。
- 归档项目后台只读，插件不再显示；服务端拒绝归档项目后续写入。
- 重复请求按幂等键重放，过期修订显示冲突且不显示本地成功；刷新操作重新读取服务端资源。
- 页面不出现代码源、任务、Run、Git、Workspace 或本地路径操作的占位成功入口。
